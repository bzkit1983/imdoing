# 字串表（i18n）

- 活線：`godot/game`
- **UI 表：** `locale/strings.csv`（欄：`key`, `zh_TW`, `en`）— 選單／HUD 殼層
- **內容表：** `locale/data.csv`（同欄）— 技能／SKU／傢俬／污物／方向／技能組預設名；未來事件／劇情／log／mood
- 執行期：Autoload **`Loc`**（`scripts/loc.gd`）— 啟動時合併讀兩張 CSV，不依賴編輯器產生的 `.translation`
- **Web／桌面匯出：** `*.csv.import` 必須用 `importer="keep"`，否則 Godot 會把 CSV 匯成 `.translation`，匯出後 `FileAccess` 讀不到原文表，畫面會顯示 key
- 預設語系：`zh_TW`（與 `project.godot` `locale/fallback` 一致）
- Agent 流程（任何 coding agent）：根目錄 [`AGENTS.md`](../../AGENTS.md) → [`agents/skills/i18n-content/SKILL.md`](../../agents/skills/i18n-content/SKILL.md)

## 用法

```gdscript
Loc.t("pause.title")
Loc.t("hud.revenue", [rev, stolen])  # 對翻譯字串做 % 格式化
Loc.t("skill.carry_boost.name")
Loc.set_locale("en")                 # Steam／英文包時切換
```

內容顯示慣例：

- 技能：`Skills.localize(sk)`／`Skills.catalog()` → `skill.<id>.name`／`.blurb`
- SKU：`Tuning.sku_name(id)` → `sku.<id>`
- 傢俬：`state.furniture_name(type)` → `furniture.<type>`
- 污物／方向：`Tuning.dirt_type_name`／`Tuning.dir_name`

## 設計文件 vs 玩家字串

- `docs/systemdesign/` **只寫中文**（設計真相）；不要把整份設計翻成多語。
- 每個玩家可見條目應有 `程式 id: \`...\``。
- 改設計名稱／說明時，**同一次變更** upsert `locale/data.csv`（或 UI 則 `strings.csv`）的 `zh_TW` + `en`，並讓 runtime 走 `Loc.t`。

## 加字串

1. 選表：UI → `strings.csv`；內容 → `data.csv`
2. 加一列 `key,zh_TW,en`（換行寫成 `\n`；含逗號的欄位加雙引號；`en` 不可空）
3. 程式改 `Loc.t("your.key")`（或上述 helper）
4. 若子集字型缺新字：`python3 tools/fonts/subset_notosans_tc.py`
5. 可選：`Loc.set_locale("en")` 煙測英文欄
6. `python3 tools/i18n_harvest.py` 確認沒有新殘留 CJK 字面值

## 規則

- Key 用穩定英文路徑（`prep.home.open`、`skill.carry_boost.name`），不要用中文當 key
- 兩張表的 key **全域不可重複**（`Loc` 會對重複 key 報錯）
- 玩法資料目錄只留機械欄位 + `id`；顯示字進 CSV
- `*.translation` 仍 gitignore；本方案不依賴 Godot CSV Translation 匯入
- 不要為語系複製 `godot/game`（見 `docs/versioning.md`）
- 加第三語：兩張 CSV 都加欄（如 `ja`），填完即可；`Loc` 依 header 動態載入
